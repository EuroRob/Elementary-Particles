## What changed because of this

The first run of these numbers (2026-11-14) showed agent commits followed by a fix five times as often as human-only commits in the same period, a six-minute median from pull request to merge, and review comments on 2 of 68 pull requests: review happened in the agent session, and nothing ran the tests or any validation automatically. In response, the repository got a Forgejo Actions pipeline on its own isolated runner (`scripts/ci/check.sh`: YAML, Python, shell, Terraform formatting, Ansible syntax, 300 offline tests, secret scan on every pull request) and a pull-request template that asks for what changed, what ran, known risks and what needs a human look. The next recomputation is the test of whether the follow-up-fix rate drops; first-pass validation (did the checks pass on the first push) becomes measurable from the pipeline's history.

## How to read this

- The follow-up-fix rate is an upper bound on rework: it counts any later fix on the same files, whether or not the agent's change caused it. Comparing it with the human-only rate is the useful part.
- Fast merges reflect a one-reviewer repository: the reviewer is the person who asked for the change and read it as it was produced. The number to watch over time is reverts of agent commits.
- Pull-request figures need `--prs` with an export from the git host's API; the git-only figures work on any clone.
